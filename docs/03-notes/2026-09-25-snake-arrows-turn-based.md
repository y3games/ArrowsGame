# 긴 화살표·공유 보드·턴제 (2026-09-25)

## 무엇을 바꿨는가

참고한 앱(Easybrain의 화살표 퍼즐)처럼 **미로같이 긴 화살표를 제거하는 게임**으로 바꾸고, 두 사람이 **한
보드를 같이 쓰며 번갈아** 플레이하도록 규칙을 재설계했다. 스토어 페이지 내용을 자동으로 읽어오지 못해
알고 있는 이 장르의 규칙(구부러진 선 + 화살촉, 탭하면 머리 방향으로 밀려 나감, 앞이 막히면 실패)을
사용자에게 확인받고 그대로 만들었다.

- **화살표**: 한 칸짜리 삼각형에서, 여러 칸에 걸쳐 꺾이는 뱀 모양으로. `Arrow = { id, cells(꼬리→머리),
  dir }`. 머리 앞 직선 경로에 다른 화살표(몸통 어느 칸이든)가 있으면 막힌다. 제거하면 머리 방향으로
  몸통이 따라 미끄러져 나간다(`arrowGraphics.ts`, 보드 영역 밖은 마스크로 잘라 HUD를 침범하지 않게 함).
- **공유 보드·양쪽 표시**: 한 사람이 제거하면 상대 화면에서도 같은 화살표가 사라지고, 실패(막힌 화살표를
  누름)도 상대 화면에 빨간 깜빡임과 `-1`로 보인다. 서버가 `attempt:result`를 양쪽에 똑같이 보낸다.
- **턴제와 점수**: 제거 +1, 실패 -1과 즉시 턴 종료, 제한 시간 초과는 감점 없이 턴 종료. 보드가 비면
  점수 높은 쪽이 라운드 승리(동점이면 무승부 라운드). 3판 2선승 유지, 선공은 첫 라운드 무작위 →
  이후 진 사람이 먼저(무승부면 서로 교대).
- **턴 시간**: 라운드 첫 턴 5초, 이후 모든 턴 10초, 제거해도 다시 채워지지 않음. 상단 링이 남은 턴
  시간을 보여주고(내 턴은 파랑, 상대 턴은 주황), HUD에 "나 N : 상대 N", 내 차례/상대 차례, 남은 화살표.

## 해석하고 정한 것 (사용자 확인이 필요하면 바꿀 곳)

- "최초 선 사용자 5초 후, 이후 턴은 10초씩 무한 반복"을 **각 라운드의 첫 턴은 5초, 그 뒤 모든 턴은
  10초**로 해석했다. `packages/shared/src/game/config.ts`의 `FIRST_TURN_MS` / `TURN_MS`에서 바꾼다.
  (매치 첫 턴에만 5초로 하려면 `roundState.createRoundState`와 `Match.startRound`를 손봐야 한다.)
- 한 턴의 시간은 **고정 예산**이다(제거해도 충전 없음). 연속 제거를 하려면 빨리 눌러야 한다.
- "턴 마치기" 버튼은 두지 않았다. 틀리거나 시간이 다할 때까지 계속 눌러야 하므로, 안전하게 멈추는
  선택은 없다.
- 매치가 무승부 라운드 때문에 2승이 안 나오면 3라운드까지 진행하고 라운드 승수 → 누적 점수 순으로
  가린다. 그래도 같으면 무승부다(결과 화면에 "무승부").
- 화살표 점수는 길이와 무관하게 개당 1점이다.

## 어떻게 만들었는가

- `shared`: `types.ts`(Arrow), `board.ts`(뱀 생성·역순 배치 보장), `rules.ts`(탈출 판정),
  `roundState.ts`(`applyMove`/`passTurn`/`getRoundWinner`), `match.ts`(무승부·누적 점수·`nextFirstPlayer`),
  `config.ts`(초기 9×9·길이 2~7 → 아래 후속 변경, 턴 시간, 점수), `protocol.ts`(`round:start`에 `first`/`startsInMs`,
  `turn:start`, 양쪽 방송 `attempt:result`; `opponent:progress` 제거). 이전 `applyAttempt`,
  `currentWindowStart`와 시간 경쟁 규칙은 삭제했다.
- `server/Match.ts`: 턴 타이머(`setTimeout`)와 라운드 시작 대기 타이머를 서버가 쥐고, 모든 종료 경로
  (라운드 종료, 접속 종료)에서 정리한다.
- `client`: `arrowGraphics.ts`, `GameScene`(뱀 그리기·탭 영역·슬라이드/깜빡임/점수 팝업), `UIScene`(점수,
  턴, 링, 카운트다운에 선공 표시), 결과 화면의 승/패/무승부 요약.

## 알아둘 점

- 프로토콜이 다시 바뀌었으므로 배포할 때 Render 서버와 GitHub Pages 클라이언트를 **함께** 올려야 한다.
- 화살표 색은 겹쳐 보이지 않게 가시성용으로 돌려 쓰는 팔레트다(게임 규칙과 무관).
- 서버 로직은 소켓 클라이언트 스크립트로, 화면은 Chrome 두 탭으로 직접 확인했다. 배포 환경에서는 아직
  확인하지 않았다.

## 후속 변경: 18×18, 복잡도 상향, 순서 표시 (2026-09-25)

- **보드 18×18**: 칸이 34px(캔버스 640px 기준)이 되었다. 보드 위치(`GRID_TOP` 176, 좌우 여백 12)와 HUD 좌표를
  다시 잡았고, 화살표 두께·머리 크기는 칸 크기에 비례하므로 그대로 따라간다.
- **복잡도**: 화살표 길이 4~16, 직진 확률 0.3(`ARROW_STRAIGHT_BIAS`), 얽힘 후보 10개(`BOARD_INTERLOCK`), 채움
  목표 0.88. 측정 결과(18×18, 30판 평균): 화살표 약 42개, 평균 길이 6, 최장 16, 화살표당 꺾임 약 2.2회. 9×9
  초기 설정(길이 2~7, 꺾임 0.9회)보다 눈에 띄게 얽힌다. 얽힘 후보 수를 키우면 의존 사슬은 조금씩 길어지지만
  생성 시간이 늘어(후보 10개에 약 50ms) 여기서 멈췄다. 처음부터 막혀 있는 화살표 비율은 크기·길이와 상관없이
  40% 안팎으로 거의 변하지 않았다(역순 배치의 성질).
- **순서 표시**: 보드 테두리가 내 턴이면 파랑, 상대 턴이면 주황이 되고, 하단에 "내 차례"/"상대 차례" 배너(색
  채움), 턴이 바뀔 때 보드 중앙에 큰 "내 차례!"/"상대 차례" 팝업이 잠깐 뜬다. 라운드 시작 카운트다운은 큰
  숫자와 함께 "내가 먼저 시작합니다"(파랑)/"상대가 먼저 시작합니다"(주황) 라벨을 색 채움으로 보여 준다.
- **시계 안 남은 시간**: 상단 링 한가운데에 남은 초를 숫자로 표시한다(내 턴 마지막 3초는 빨강).
- "시작할 때 둘 다 '상대 시작'으로 보인다"는 제보는 로컬에서 재현되지 않았다(두 화면이 각각 "내가"/"상대가"로
  갈렸다). 글자가 작고 흐렸던 것이 원인일 수 있어 위처럼 눈에 띄게 바꿨고, 여러 라운드에 걸쳐 두 화면의 표기가
  서로 다르고 실제 차례와 일치하는지를 자동으로 검증해 두었다. 배포 환경에서 다시 보이면 알려 달라.

## 후속 변경: 싱글 모드 (2026-09-25)

- **규칙**: 3분 안에 모든 화살표를 제거하면 클리어, 막힌 화살표를 누를 때마다 남은 시간 -10초, 0이 되면
  실패. 보드는 멀티와 같은 18×18. 점수는 없고 클리어 시 남은 시간이 결과다.
- **해석하고 정한 것**: "틀리면 10초씩 시간 차감"을 남은 시간에서 10초를 빼는 것으로 해석했다(시계가 3분에서
  줄어들다가 실수하면 10초 뛰어 내려감). 실수해도 보드는 변하지 않는다. 최고 기록 저장·랭킹은 만들지 않았다.
- **서버 권위**: 멀티와 같은 이유로 클라이언트가 아니라 서버가 시계와 판정을 쥔다. `shared/game/solo.ts`의
  `applySoloMove`/`soloTimeLeftMs`(순수 함수)를 `server/SoloGame.ts`가 쓰고, 실수마다 마감이 앞당겨지므로
  시간 초과 타이머를 다시 건다. 프로토콜: `solo:start`/`solo:click`/`solo:leave` → `solo:started`/
  `solo:result`/`solo:finished`. 남은 시간은 서버가 "지금 기준 N밀리초"로 내려보내 클라이언트가 자기
  `performance.now()`에 맞춰 마감을 계산한다.
- **소켓 상태**: 한 소켓은 방에 있거나 싱글 중이거나 둘 중 하나다(양방향으로 거부). 싱글 중에는 로비 방 목록을
  받지 않고, 끝나거나 나가면 로비로 복귀시키며 목록을 다시 보낸다. 연결이 끊기면 게임을 버린다.
- **화면**: 로비의 "싱글 플레이 (3분)" 버튼(닉네임 불필요), 게임 중 좌상단 "나가기" 버튼, 링 안의 `m:ss` 시계(마지막
  30초 빨강), "실수 N회"와 남은 화살표, 실수 시 중앙에 `-10초`, 결과 패널(클리어/시간 초과, 남은 시간·걸린 시간·
  실수·제거 수, 다시 하기·로비로).
- 멀티 게임 도중 "나가기" 버튼은 이 시점에는 싱글 전용이었고, 아래 후속 변경에서 멀티에도 추가했다.

## 후속 변경: 멀티 도중 나가기 버튼 (2026-09-25)

- 매치 진행 중(카운트다운·라운드 사이 포함)에는 좌상단에 "나가기" 버튼이 보이고, 결과 화면이나 방 대기 화면(자체
  "나가기" 버튼이 있음)에서는 숨는다. 누르면 "지금 나가면 이 대전은 패배로 처리됩니다" 확인 창이 뜨고, 확인하면
  `room:leave`를 보낸다. 서버는 이미 도중 퇴장을 상대의 승리로 처리하고(재대결 창 없이, 남은 사람은 방에서 1/2로
  대기) 나간 사람은 `room:left`로 로비에 돌아간다 — 서버 변경은 없다.
- 싱글의 "나가기"는 패널티가 없어 확인 창 없이 바로 나간다. 같은 버튼을 `GameScene.exitGame()`이 phase에 따라
  구분한다.

## 후속 변경: 한 칸 화살표 제거, 30×30, 싱글 레벨제 (2026-09-25)

- **한 칸짜리 화살표 제거**: `MIN_ARROW_LENGTH = 2`. `generateBoard`는 minLength 1을 요청해도 2로 올리고, 틈 메우기
  단계도 2~3칸만 놓는다(이전에는 1~3칸). 머리 방향 분기(한 칸이면 아무 방향)도 없앴다.
- **멀티 30×30**: 칸이 20px(캔버스 640px 기준)이라 꽤 작다. 레이아웃을 고정값이 아니라 **보드 크기에서 계산**하도록
  바꿨다(`config.ts`의 `setBoardSize`, `getCellSize`(폭·높이 중 작은 쪽에 맞춤), `getGridLeft/Top`(가운데 정렬)). 화살표
  두께·머리는 칸이 작아도 최소 크기를 유지한다. 그리드 점과 마스크는 보드 크기가 바뀔 때만 다시 만든다.
- **생성기 개선 두 가지**
  - *조기 종료*: 이전에는 실패해도 정해진 횟수를 다 돌아 30×30에서 0.5초까지 걸렸다(서버 이벤트 루프를 막는다).
    이제 연속 실패가 `max(200, 칸 수)`를 넘으면 다음 단계로 넘어가 약 20~50ms다.
  - *중앙 당김(`centerPull`)*: 30×30에서 가운데가 비고 가장자리만 꽉 차던 문제(가운데 채움 0.33 대 0.65)를 시작 칸을
    "여러 번 뽑아 중앙에 가까운 것"으로 고르게 해서 풀었다. 얽힘 옵션이 원인이 아니었다(옵션 1에서도 같았다). 당김을
    키우면 화살표가 늘어 난이도 손잡이로도 쓴다.
- **싱글 레벨제**: `soloLevelConfig(level)`(shared/solo.ts). 레벨 1 = 10×10(화살표 약 17개), 레벨마다 +2칸씩 커져 레벨 11에서
  30×30(약 100개). 이후 레벨 20까지 최대 길이(24), 직진 확률(0.1), 얽힘(14), 중앙 당김(10), 최소 길이(5)가 계속 올라간다.
  시간은 계속 3분, 실수 -10초다. 클리어하면 다음 레벨(`localStorage`에 저장), 실패는 같은 레벨 재도전, 나가기는 레벨
  유지, "레벨 1부터 다시 시작" 링크로 초기화. 결과 패널에 다음 레벨의 맵 크기가 나온다.
- **알아둘 점**: 레벨 11에서 화살표가 약 100개라 3분에 1.8초/개 페이스가 필요해 꽤 어렵다. 너무 어렵다면 시간 제한을
  화살표 수에 비례시키거나 레벨 곡선의 `centerPull`을 낮추면 된다. 저레벨은 무작위 편차 때문에 다음 레벨의 화살표가
  드물게 더 적을 수 있다(평균은 늘어난다). 진행 레벨은 브라우저 저장소에만 있어 기기를 바꾸면 사라진다.

## 후속 변경: 효과음과 배경음악 (2026-09-25)

- **방식**: 음원 파일이나 MIDI 재생 라이브러리 없이 **Web Audio로 코드에서 합성**한다. 용량이 늘지 않고 저작권 문제가
  없다. "MIDI 배경음악"은 음표 데이터(`audio/score.ts`)를 시퀀서(`engine.ts`)가 연주하는 방식으로 구현했다(사각/톱니파 리드,
  삼각파 베이스, 킥·스네어·하이햇). 정식 .mid 파일을 쓰려면 파서와 음색(사운드폰트)이 필요해 크기가 훨씬 커진다.
- **곡**: 명랑한 곡 = C장조 132bpm 16마디(약 29초)를 무한 반복. 긴장 곡 = A단조+E장조 딸림화음 172bpm 8마디(약 11초)
  루프, 매 박 킥(심장 박동)과 쉬지 않는 베이스. 싱글에서 남은 시간이 10초 이하가 되면 명랑 → 긴장으로 0.25초 페이드로
  전환하고, 끝나거나 나가면 명랑으로 돌아온다. 멀티는 턴이 항상 10초 이하라 전환하지 않는다(내 턴 마지막 몇 초만 긴장시키는
  식으로 바꿀 수는 있다).
- **효과음**: 제거 = 위로 훑는 노이즈 + 올라가는 팝 + 종소리, 실패 = 둔탁한 쿵 + 떨어지는 부저. 멀티에서는 상대의 제거음이
  더 낮고 작아 누구의 탭인지 구분된다(실패음은 같다).
- **브라우저 정책**: 첫 클릭·키 입력 전에는 소리를 낼 수 없어(`AudioContext`가 잠김) 그 전에는 재생하지 않고 곡 선택만 기억한다.
  탭이 숨겨지면 컨텍스트를 멈춘다(타이머 스로틀로 음악이 끊기는 것을 막음). 우상단 ♪ 버튼(로비 오버레이 위)으로 음소거하고
  `localStorage`에 기억한다.
- **테스트 환경**: 클라이언트에 vitest를 추가했다(`npm run test`가 shared와 client를 모두 돈다). 합성 함수가 `BaseAudioContext`를
  받으므로 오프라인 렌더링으로 소리를 듣지 않고도 무음·클리핑을 점검할 수 있다.
- **한계**: 곡의 좋고 나쁨은 사람이 들어야 안다. 음악 세기(`MUSIC_LEVEL`), 효과음, 곡의 음표는 `audio/` 안의 상수·데이터만
  고치면 된다.

## 후속 변경: 진행 효과음 — 턴 전환·시작·종료 (2026-09-25)

- **추가한 소리**(`audio/synth.ts`, 종류는 `engine.ts`의 `SfxKind`): 카운트다운 삑(초마다), 시작 "go"(싱글), 내 턴 알림(올라가는
  두 음), 상대 턴 틱(작고 낮은 한 음 — 내 차례가 아니므로 일부러 조용), 라운드 승리(위로 아르페지오)/패배(아래로 세 음)/무승부(같은
  음 두 번), 최종 승리 팡파르(끝에 화음)/패배(천천히 하강 + 낮은 음)/무승부.
- **어디서 울리나**: 이벤트를 이미 받는 `UIScene`에서 울린다. 카운트다운은 표시하는 숫자가 바뀔 때마다(초당 1회), 싱글은 카운트다운이
  끝나는 순간 "go"(멀티는 서버의 첫 `turn:start`가 시작이므로 알림음이 그 역할). 턴 전환음은 그 턴 전환을 일으킨 탭의 효과음과 안
  겹치게 0.18초 늦춘다(`playSfx`의 `delay`).
- **매치 마지막 라운드**: `round:finished` 직후 `match:finished`가 오므로 라운드 효과음은 200ms 뒤에 울리게 예약하고, 매치 종료가
  오면 취소한다. 그래서 마지막 라운드에는 종료음(팡파르/패배음)만 난다.
- **Phaser 오디오 끔**: Phaser가 자체 `AudioContext`를 하나 더 열고 있었다(우리는 쓰지 않음). `audio: { noAudio: true }`로 꺼서
  컨텍스트가 하나만 남는다.
- **한계**: 곡·효과음의 취향은 사람이 들어야 안다. 멀티에서 내 턴 마지막 몇 초에 째깍거리는 경고음을 넣는 것 등은 아직 없다.

## 후속 변경: 더 밝은 배경음악, 게임판 가운데 정렬 (2026-09-25)

- **배경음악을 밝게**(명랑한 곡만, 긴장 곡은 그대로): 템포 132 → 152bpm(루프 약 25초), 가장 밝은 코드 진행인 I–V–vi–IV(C G Am F)로
  변경, 멜로디를 한 옥타브 가까이 높이고(평균 음높이 MIDI ~79 → 80대 중반), 리드의 저역 통과 필터를 3200 → 6500Hz로 열었다.
  거기에 ① 모든 멜로디 음에 한 옥타브 위 종소리 같은 짧은 배음(`sparkle`)과 ② 뒷박마다 코드를 짧게 치는 스타카토(`stabs`,
  "움-파")를 더했다. 두 번째 8마디는 한 단계 더 높이 올라갔다가 처음으로 돌아온다.
- **밝기 측정**(오프라인 렌더링 20초, FFT): 스펙트럼 무게중심 696 → 935Hz(+34%), 1.5kHz 이상 에너지 비율 8.4 → 15.2%, 음량은 비슷하고
  클리핑 없음. 악보 테스트에 평균 음높이·템포·스타카토 위치/코드(C는 장3도, Am은 단3도) 검증을 추가했다(17개).
- **게임판 가운데 정렬**: 원인은 **이중 가운데 정렬**이었다. `#app`의 CSS flex 정렬과 Phaser의 `autoCenter: CENTER_BOTH`가 둘 다 캔버스
  여백을 넣어, 창이 클수록 게임이 한쪽으로 밀렸다(1920×1080에서 300px, 1280×800에서 186px, 모바일 세로에서 위아래로 64px). `NO_CENTER`로 바꿔
  CSS 정렬 하나만 남겼다. 5가지 화면 크기(700×980, 1280×800, 1920×1080, 390×844, 1024×1366)에서 캔버스와 **게임판 자체**의 중심이 창 중심과
  0.0px 차이임을 확인했고, 세 크기에서 실제 마우스 탭이 여전히 화살표를 제거함을 확인했다.

## 후속 변경: 동요풍 배경음악, 레벨에 따른 템포 (2026-09-25)

- **요청**: 더 밝게, 동요 같은 느낌으로, 지금보다 조금 느리게, 레벨이 오르면 아주 조금씩 빨라지게.
- **곡**: 152bpm의 신나는 곡에서 **120bpm의 동요풍**으로 다시 작곡했다. 짧은 프레이즈를 반복하고(1~4마디를 5~8마디에서 되풀이, 13~16마디는
  한 옥타브 위), 계단식·작은 도약 위주라 따라 부르기 쉽다(테스트가 "음 이동의 75% 이상이 4반음 이내"와 반복 구조를 확인). 코드는 C·F·G 위주
  (I–IV–V)에 다리 구간(Am–Dm–G–C)이 있다. 음색은 오르골/실로폰: 부드러운 삼각파 리드 + 유리 같은 사각파 얇은 층 + 한 옥타브 위와 5도 위
  종소리 배음, 가벼운 뒷박 코드 "플링크", 스네어 없이 살짝 툭·틱만(드럼 스타일 `gentle`).
- **밝기를 수치로 맞춤**: 처음 버전은 삼각파 리드와 두꺼운 저음 때문에 오히려 더 어두웠다(무게중심 655Hz). 리드에 사각파를 얹고 종소리를 키우고
  베이스·킥을 줄여 이전(152bpm) 곡보다 밝게 맞췄다. 20초 렌더링, 무게중심 / 1.5kHz 이상 에너지: 원래 곡 696Hz / 8.4%, 직전 배포 곡
  935Hz / 15.2%, **새 곡 962Hz / 17.3%(120bpm)·1001Hz / 19.8%(144bpm)**, 음량은 직전 곡과 비슷(RMS 0.146 대 0.159).
- **레벨별 템포**: `cheerfulBpm(level) = min(144, 120 + 2 × (level − 1))`. 레벨 5는 레벨 1보다 8% 정도만 빠르고, 레벨 13부터 144에서 멈춘다(긴장
  곡 172와는 여전히 뚜렷하게 차이). 싱글 시작 때 `setLevel(레벨)`, 로비·멀티에서는 1로 되돌아간다. 런이 끝난 결과 화면에서는 그 레벨의 템포가
  유지되다가 로비로 나가면 120으로 돌아간다. 긴장 곡은 172로 고정.
- **한계**: 곡의 취향은 사람이 들어야 안다. 멜로디는 `score.ts`의 CHEERFUL 마디 데이터, 템포 곡선은 `CHEERFUL_*` 상수를 고치면 된다.
