# 방 만들기·입장·다시 하기 투표 (2026-09-25)

## 무엇을 했는가

- **방 기반 입장**: 무작위 대기열(`queue:join`/`queue:leave`/`queue:waiting`, `matchmaking.ts`)을 없애고
  방으로 대체했다. 로비에서 "방 만들기"를 누르면 방이 "1/2"로 목록에 뜨고, 다른 사용자가 목록의 "입장"을
  누르면 "2/2"가 되며 매치가 자동으로 시작된다. 가득 찬 방·게임 중인 방·결과 화면 중인 방은 입장할 수
  없다(서버가 `room:error` `full`로 거부하고, 목록에서는 버튼이 "가득 참"/"게임 중"으로 비활성화된다).
- **다시 하기 투표**: 매치가 끝나면 서버가 `rematch:open { timeoutMs: 10000 }`을 보내고 결과 화면에
  "다시 하기"/"나가기"와 남은 시간이 나타난다. 둘 다 누르면 같은 방에서 새 매치가 시작된다. 10초 안에
  누르지 않은 사람은 서버가 `room:left { reason: 'timeout' }`로 방에서 내보내 로비로 돌려보낸다.
- **한 명이 나갔을 때**: 나가기 버튼, 10초 초과, 접속 종료 모두 남은 사람이 방에 남아 1/2로 새 상대를
  기다린다(방장 승계). 남은 사람의 결과 화면에는 "상대가 방을 나갔습니다"가 뜨고 다시 하기 버튼은
  숨겨진다. 이때 새 사람이 입장하면 결과 화면에서 곧바로 새 매치로 넘어간다. 매치 도중 나가면 남은
  사람이 승리 처리되며 재대결 창은 열리지 않는다.

## 어떻게 만들었는가

- `packages/shared/src/game/room.ts` — 소켓을 모르는 순수 함수(`createRoom`, `canJoin`, `addPlayer`,
  `removePlayer`, `voteRematch`, `playersWhoDidNotVote`, `toSummary` 등)와 vitest 테스트. 상수는
  `ROOM = { CAPACITY: 2, REMATCH_WINDOW_MS: 10_000 }`.
- `packages/server/src/rooms.ts` — `RoomManager`가 소켓, 재대결 타이머, 진행 중인 `Match`를 관리한다.
  방에 없는 소켓은 Socket.IO room `lobby`에 두고 방 목록이 바뀔 때마다 `rooms:list`를 보낸다.
  `leave()`는 `Match.handleDisconnect()`를 부르기 전에 `entry.match`를 떼어 내, 기권승이 정상 종료로
  처리되어 재대결 창이 열리는 일을 막는다. 남은 재대결 타이머는 모든 퇴장·시작 경로에서 해제한다.
- 클라이언트: `index.html`의 로비 패널(방 만들기 + 방 목록), 방 대기 패널, 결과 패널(다시 하기/나가기 +
  10초 표시), `ui/lobby.ts`, `GameScene`(`match:found`마다 `resetMatch()` 후 시작). 남은 시간 표시는
  서버가 준 `timeoutMs`에서 로컬로 세는 표시용이고, 실제 퇴장은 서버가 결정한다.

## 알아둘 점

- 프로토콜이 바뀌었으므로 배포할 때 **Render 서버와 GitHub Pages 클라이언트를 함께** 갱신해야 한다.
  한쪽만 새 버전이면 방 이벤트가 오가지 않아 로비에서 아무것도 할 수 없다.
- 방 제목은 방장 닉네임으로 자동 생성한다(`{닉네임}의 방`). 별도 제목 입력·비밀번호·관전은 범위 밖이다.
- 재접속 복구는 여전히 없다. 접속이 끊기면 방에서 제거된다.
- 로컬 개발 서버 포트 4000을 다른 프로세스가 쓰고 있으면 `PORT=4100`으로 서버를 띄우고
  `VITE_SERVER_URL=http://localhost:4100`으로 클라이언트를 띄워 확인할 수 있다.
