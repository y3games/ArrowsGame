# 화살표 탈출 미로 — 게임 개요 및 규칙

## 개념

보드 위에 미로처럼 구부러진 **긴 화살표(뱀 모양)** 여러 개가 얽혀 있다. 화살표는 여러 칸에 걸친 선이고
한쪽 끝(머리)에 화살촉이 있다. 화살표를 누르면 머리가 가리키는 방향으로 몸통이 따라가며 보드 밖으로
밀려 나간다. 머리 앞쪽 직선(보드 가장자리까지)에 **다른 화살표가 한 칸이라도 있으면 막혀서 나가지
못한다.** 막히지 않은 화살표를 골라 하나씩 내보내 보드를 비우는 퍼즐이다.

이를 실시간 1:1 온라인 대전으로 만든다. 두 사람이 **같은 보드를 함께 쓰며 번갈아** 화살표를 내보낸다.

## 핵심 규칙

- **하나의 보드를 공유한다.** 한 사람이 화살표를 제거하면 상대 화면에서도 같은 화살표가 사라진다.
  막힌 화살표를 눌러 실패한 것도 상대 화면에 그대로 보인다(빨간 깜빡임과 `-1`).
- **턴제.** 자기 턴에는 여러 화살표를 연달아 제거할 수 있다.
  - 제거에 성공하면 **+1점**, 턴은 계속된다.
  - 막힌 화살표를 누르면 **-1점**이고 **그 즉시 턴이 상대에게 넘어간다.**
  - 턴에는 제한 시간이 있고, 시간이 다 되면 **감점 없이** 턴이 상대에게 넘어간다. 제거해도 시간이
    다시 채워지지 않는다(턴 전체가 한 번의 제한 시간). 라운드의 첫 턴은 5초, 이후 모든 턴은 10초이며
    이것이 라운드가 끝날 때까지 반복된다.
  - 자기 턴이 아닐 때 누른 것은 무시된다.
- **라운드.** 보드의 화살표가 모두 없어지면 끝나고, **점수가 높은 쪽이 라운드를 이긴다.** 점수가
  같으면 무승부 라운드다. 라운드가 시작될 때 3초 카운트다운이 있다.
- **선공.** 첫 라운드의 선공은 무작위, 2라운드부터는 **직전 라운드에서 진 사람이 먼저** 시작한다
  (무승부면 선공이 서로 바뀐다).
- **매치 구조: 3판 2선승제.** 라운드마다 새 보드를 무작위로 생성한다. 2승을 먼저 달성하면 매치에서
  승리한다. 무승부 라운드가 끼어 2승이 나오지 않으면 3라운드까지 진행한 뒤 라운드 승수로, 승수가
  같으면 누적 점수로 가리고, 그것도 같으면 무승부다.
- **1:1 대전.** 한 매치에 두 명이 참가하며, 상대방이 접속을 종료하면 즉시 남은 플레이어의
  승리로 매치가 종료된다.
- **싱글 모드.** 로비의 "싱글 플레이"로 혼자 하는 모드다. 같은 18×18 보드의 화살표를 **3분 안에 모두**
  제거하면 클리어이고, **막힌 화살표를 누를 때마다 남은 시간에서 10초가 깎인다**(보드는 그대로). 남은
  시간이 0이 되면(실수로 깎여서 0이 되는 것 포함) 실패다. 별도 점수는 없고 클리어 후 **남은 시간**이
  기록이다. 시작 전 3초 카운트다운이 있고, 끝나면 "다시 하기"(새 보드)나 "로비로", 도중에는 "나가기"로 그만둘 수 있다.
  멀티와 마찬가지로 시간과 판정은 서버가 쥔다.
- **방(room) 기반 입장.** 로비에서 방을 만들면 "1/2"로 표시되고, 다른 사용자가 방 목록에서 입장해
  "2/2"가 되면 게임이 자동으로 시작된다. 가득 찬 방이나 게임 중인 방에는 입장할 수 없다.
- **다시 하기 투표.** 매치가 끝나면 두 플레이어에게 "다시 하기"/"나가기"가 나타난다. 둘 다 10초 안에
  "다시 하기"를 누르면 같은 방에서 새 매치가 시작된다. 10초 안에 누르지 않은 사람은 자동으로 방에서
  나가 로비로 돌아가고, 남은 사람은 방에 남아 1/2로 새 상대를 기다린다(나가기 버튼·접속 종료도 같다).

## 기술 스택

- 클라이언트: Phaser 3 + Vite + TypeScript (`packages/client`)
- 서버: Node.js + Socket.IO + TypeScript (`packages/server`)
- 공유 로직: `packages/shared` — 보드 생성, 탈출 판정, 시도/라운드/매치 상태 전이를 모두 Phaser에
  의존하지 않는 순수 함수로 구현하고 클라이언트·서버가 그대로 import해서 쓴다.

## 서버 권위(authoritative) 설계

서버가 유일하게 신뢰되는 시계이자 심판이다. 클라이언트가 보내는 것은 `attempt:click` 하나뿐이고,
누구의 턴인지, 제거인지 실패인지, 턴이 끝났는지는 서버가 도착 시각을 기준으로 `@arrows/shared`의
`applyMove()`로 판정하고 턴 타이머도 서버가 쥔다. 결과는 `attempt:result`(제거/실패, 누가, 점수)로
**양쪽 플레이어에게 똑같이** 보내고, 클라이언트는 그 이벤트로만 화면을 바꾼다. 남은 턴 시간은 서버
시각이 아닌 "지금부터 N밀리초"(`durationMs`)로 내려보내 두 기기의 시계 차이에 영향을 받지 않는다.
공유 보드이므로 두 사람이 동시에 누를 일이 없다(자기 턴에만 유효). 지연시간 보정 같은 고급
안티치트는 캐주얼 게임이라는 전제 하에 범위에서 제외했다.

## 보드 생성 알고리즘

무작위 탈출 순서를 먼저 정한 뒤, 그 **역순**으로 빈 보드에 화살표를 하나씩 배치한다. 화살표는 빈 칸에서
시작하는 무작위 자기회피 경로(뱀)이고 머리는 마지막 구간의 방향을 가리킨다. 새 화살표는 머리 앞
가장자리까지의 직선이 **그 시점까지 놓인 모든 화살표(자기 몸 포함)와 겹치지 않을 때만** 받아들인다.
나중에 놓은 것이 먼저 나가므로 그 앞을 막는 것은 오직 먼저 놓인 것들뿐이고, 따라서 완성된 보드는
항상 끝까지 풀 수 있음이 구성 과정 자체로 보장된다(휴리스틱이 아니라 증명 가능한 보장).
**18×18** 보드에 길이 4~16칸의 화살표를 놓고, 남는 틈은 1~3칸짜리로 메운다(칸의 약 75%가 채워지고 화살표는
40개 안팎, 화살표당 평균 꺾임 약 2회). 복잡도는 세 가지 값으로 조절한다: 길이 범위, 직진 확률
`ARROW_STRAIGHT_BIAS`(낮을수록 구불구불), 그리고 얽힘 `BOARD_INTERLOCK` — 한 자리를 정할 때 후보 뱀을 여러 개
뽑아 이미 놓인 화살표들의 진행 경로를 가장 많이 가로지르는 것을 고르므로 "이게 먼저 나가야 저게 나간다"는
의존 사슬이 길어진다. 보드 생성에 약 50ms가 걸리지만 서버가 라운드당 한 번만 하므로 문제없다.
자세한 구현은 `packages/shared/src/game/board.ts` 참고.

## 검증 상태

- `packages/shared`: 긴 화살표 보드 생성(여러 크기·시드에서 항상 끝까지 풀림, 칸 겹침 없음, 머리 방향,
  채움률), 탈출 판정(몸통 어느 칸이든 길을 막음), 턴제 라운드(제거 +1·연속 제거, 실패 -1과 즉시 턴 종료,
  순서 아닌 클릭·카운트다운 중·시간 만료 후 클릭 거부, 감점 없는 턴 넘김), 3판 2선승과 무승부 라운드·
  동점 처리·다음 선공, 기본 보드(18×18)의 길이·꺾임·채움 및 얽힘 옵션 효과를 vitest로 자동 검증 (125개 테스트 통과).
- `packages/shared`의 방 로직(`room.ts`): 가득 찬 방·게임 중 방 입장 거부, 방장 승계, 다시 하기 투표
  (양쪽/한쪽/중복/타인), 미투표자 목록을 vitest로 검증 .
- 서버(Socket.IO)를 소켓 클라이언트 2개로 직접 검증(로컬, 턴제): 양쪽이 같은 보드와 선공을 받음, 첫 턴 5초,
  순서 아닌 클릭 무시, 연속 제거가 양쪽에 방송됨(제거자·점수 포함), 실패는 양쪽에 `correct:false`로
  방송되고 -1점과 함께 턴이 즉시 상대에게(10초), 실패한 사람은 그 턴에 다시 누를 수 없음, 보드가 비면
  점수 높은 쪽이 라운드 승리, 다음 라운드는 진 사람이 선공, 5초/10초 무응답 시 감점 없이 턴 넘김
  (실제 타이머 5.0초 근처), 매치 종료와 재대결 창. 방 기능(입장 거부, 다시 하기 투표, 10초 자동 퇴장,
  기권승)은 이전 작업에서 같은 방식으로 확인함. 닉네임 12자 제한, `/healthz`, 다중 CORS 출처도 확인함.
- 브라우저(Chrome, 탭 2개)로 방 입장 → 긴 화살표 보드 렌더링 → 내 차례/상대 차례 표시와 점수 → 순서
  아닌 탭이 무시됨 → 내가 제거한 화살표가 상대 화면에서도 사라짐(양쪽 화살표 수 일치) → 막힌 화살표를
  누르면 `-1`이 상대 화면에도 뜨고 턴이 넘어감까지 end-to-end로 확인함.
- 브라우저(Chrome, 탭 2개, 18×18)로 카운트다운 라벨이 한쪽은 "내가 먼저 시작합니다", 다른 쪽은 "상대가 먼저
  시작합니다"로 갈리는지, 턴 배너("내 차례"/"상대 차례")가 실제 차례와 일치하는지, 시계 안 숫자가 표시되는지, 2라운드
  에서 진 사람이 먼저 시작하는지 확인함.
- 싱글 모드: `solo.ts`(시계, 실수당 -10초, 카운트다운 중·시간 종료 후·중복 클릭 거부, 실수로 시간이 0이 되는
  경우)를 vitest로, 서버를 소켓 스크립트로(카운트다운 중 클릭 무시, 잘못된 gameId 무시, 제거/실수 응답과
  시간 차감, 클리어 결과, 실수 17번 후 서버 타이머가 남은 시간 뒤 정확히 시간 초과를 냄, 18번째 실수가 곧바로
  종료시킴, 싱글 중 방 만들기 거부, 종료·나가기 뒤 로비 복귀와 다시 하기), 브라우저로(시작·시계·`-10초` 표시·
  클리어 결과·다시 하기·나가기) 확인함. 3분을 실제로 다 기다리는 시간 초과는 하지 않았다.
- 18×18 규칙, 순서 표시 개선, 싱글 모드는 아직 배포하지 않았다. 배포하려면 서버(Render)와 클라이언트(Pages)를 함께 올려야 한다.
